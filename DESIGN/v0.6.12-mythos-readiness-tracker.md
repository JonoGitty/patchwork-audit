## The load-bearing property (read before picking any item)

Per GPT-5.5's 2026-05-29 completeness review (`REVIEWS/2026-05-29-gpt55-tracker-completeness-review.md`): **itemising bugs is not enough.** Mythos-readiness is one cross-cutting invariant:

> **Every agent-influenced path to a real-world side effect must be mediated by the same fail-closed, tamper-resistant policy authority, with durable provenance and secure human approval where required.**

That authority must cover ALL of: shell commands · package managers · interpreters (`python -c`, `node -e`) · git · environment variables (`NODE_OPTIONS`, `LD_PRELOAD`, `PYTHONPATH`, `GIT_*`) · config files · file reads (secrets!) · file writes · network egress (incl. `/dev/tcp`, DNS, static binaries) · persistence locations (`~/.zshrc`, LaunchAgents, git hooks) · approval flows · audit logs · cross-session memory/instructions · and Patchwork's own binary/config/state.

**If even one path stays "just documented," "same-user writable," "parser-based," or "best effort," a Mythos-class agent routes through it.** The taint/sink/parser work (v0.6.11) is necessary but is only one of those paths. The M-series items below are the categories the original bug-list missed.

## Definition of "all green" (REVISED 2026-05-29 after completeness review)

The original 6-bullet bar proved "known audit findings closed." It did NOT prove "safe against Mythos." The real bar is the reference-monitor property holding across every path. All ten must be true against a Glasswing-tier adversary:

1. **Complete mediation** — every agent-caused side effect (process exec, file write, file READ, network, config change, package lifecycle, git op, env change, persistence write) passes through the policy authority. Verified by M13's enumeration + M11's e2e chains.
2. **Non-bypassability** — the enforcement binary/hook/daemon cannot be replaced, downgraded, PATH-shadowed, or disabled by a same-user agent. Verified by M2 (code integrity) + F1 (alternate-name) + hardening corpus.
3. **Fail-closed operation** — no daemon / stale policy / corrupt ledger / version skew / unreadable taint / ambiguous crash recovery ⇒ high-risk actions blocked. Verified by M9.
4. **Secure human approval** — non-scriptable, canonical, provenance-aware, bound to the exact execution manifest. Verified by M3 + M4.
5. **Execution immutability** — an approved action cannot change via env, PATH, script contents, symlink, config, package manager, interpreter preload, or cwd race between approve and exec. Verified by M4 + M5.
6. **Actual egress containment** — network/filesystem/process egress is ENFORCED, not just documented. Verified by O1 (implementation).
7. **Secret protection** — reads of credentials/high-value local files are denied or brokered under taint. Verified by M1.
8. **Persistence control** — writes to startup/config/hook locations denied or brokered under taint. Verified by M6.
9. **Tamper-evident audit** — root-owned append-only ledger, signed sequence, continuity-verified. Verified by M8.
10. **End-to-end adversarial validation** — full autonomous exploit chains are blocked, not just unit-fixture classifications. Verified by M11.

Only when all ten hold can Patchwork v0.6.12 credibly be offered to Glasswing-tier users. The old 6 bullets are subsumed (1↔M13, 2↔M2/F1, 4↔M3, etc.). The UX items (U1-U6) come AFTER these, or they're "green theatre" — a green `doctor` without real enforcement is worse than no doctor.

## Workflow rhythm

The plan only works if it gets touched. Three minimum rhythms:

1. **Always update the "Next action" line at the top** when an item changes state. This is the orient-yourself anchor for the next session.
2. **One concrete commit per item** (or one branch per item if multiple commits). Items are sized so a single Claude session can complete one of them in a sitting.
3. **Cross-vendor review for design items only** (D1, P1). Code items don't need GPT-5.5 review unless they touch security-critical control flow — F1's commit message already cites the existing audit.

- **Daily** (when actively working v0.6.12): one F-or-U item per session, merged before logging off.

- **Before tagging v0.6.12**: re-run the GPT-5.5 Mythos overlay against the new state; expect to find new findings (Mythos's threat surface will keep evolving).
