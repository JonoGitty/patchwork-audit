## Definition of "all green"

The tracker hits 100% green when, against a Glasswing-tier adversary:

1. **No self-approval is possible from any agent-controlled process** (symlink, copy, wrapper, exec-modifier, package-manager invocation, ANY shape). Verified by T11 + a hardening test corpus.
2. **Policy + approval state are root-owned**, not same-user writable. Verified by D2 + integration tests that prove user-process write fails closed.
3. **Taint state is authenticated and rollback-resistant**. HMAC + monotonic counter + fsync + lstat refuse-symlink. Verified by T10 + crash-recovery tests.
4. **Cross-session provenance survives session boundary**. Verified by T9 + A13 + property-based "no fact lost across session" test.
5. **Network/filesystem/process egress is documented as not protected by hooks alone** in README. Verified by U6 + U1.
6. **A user can run `patchwork doctor --mythos-readiness` and `patchwork test-guards` to see live evidence of the defences working** before relying on them. Verified by U2 + U3.

If all six are true, Patchwork v0.6.12 can credibly be offered to Glasswing-tier users with the threat-model framing from `PATCHWORK_MYTHOS_READINESS.md` § "Secure-and-happy-to-use".

## Workflow rhythm

The plan only works if it gets touched. Three minimum rhythms:

1. **Always update the "Next action" line at the top** when an item changes state. This is the orient-yourself anchor for the next session.
2. **One concrete commit per item** (or one branch per item if multiple commits). Items are sized so a single Claude session can complete one of them in a sitting.
3. **Cross-vendor review for design items only** (D1, P1). Code items don't need GPT-5.5 review unless they touch security-critical control flow — F1's commit message already cites the existing audit.

### Suggested cadence

- **Daily** (when actively working v0.6.12): one F-or-U item per session, merged before logging off.
- **Weekly**: D-items get a focused 2-3 hour design pass with GPT-5.5 review.
- **Before tagging v0.6.12**: re-run the GPT-5.5 Mythos overlay against the new state; expect to find new findings (Mythos's threat surface will keep evolving).

### Aiorch dispatch (optional, for autonomous grinding)

For F2, F3, G1, T9-T14, U1-U6 — items that are concrete and well-scoped — `aiorch one-shot` can do the implementation autonomously per `feedback_cross_vendor_review_pattern`. Example:

```bash
aiorch one-shot "Implement F2 from DESIGN/v0.6.12-mythos-readiness-tracker.md — \
  add fsync to writeTaintSnapshot in packages/agents/src/claude-code/taint-store.ts \
  per the acceptance criteria. Open a feature branch, add one test, run lint/test/build, \
  commit with a clear message referencing the tracker. Do not push." \
  --mode balanced --budget 0.50 --context
```

(With `--context` enabled so the spine memory of the tracker is in the planner's view.)

The D-items (root-owned daemon design, cross-session provenance design) are NOT good fits for autonomous dispatch — they're load-bearing architectural decisions that want a human + cross-vendor review.
